Descrição dos Casos de Uso (E0)

Módulo 1: Autenticação e Gestão de Conta
UC01 - Registo de Utilizador
Este caso de uso tem como ator principal o utilizador normal ou visitante e não possui atores secundários. Permite a um novo utilizador criar uma conta na plataforma para poder aceder às funcionalidades do sistema. Como pré-condição, o utilizador não deve estar autenticado no sistema. Após a conclusão com sucesso, é criada uma nova conta de utilizador com o perfil de Utilizador Normal. No fluxo principal, o utilizador acede à página de registo, preenche o formulário com Nome, Email e Password, e submete o formulário. Em seguida, o sistema valida se o email já se encontra registado e se a password cumpre os requisitos de segurança, guarda o novo utilizador no sistema, exibe uma mensagem de sucesso e redireciona o utilizador para a página de login. Nos fluxos alternativos e de exceção, caso o email já exista no sistema, o software lança uma exceção do tipo EmailJaExisteException, exibe uma mensagem de erro e solicita um email diferente. Caso os dados sejam inválidos, o sistema indica os campos incorretos e solicita a devida correção.

UC02 - Efetuar Login (Autenticação)
Este caso de uso envolve como atores principais o Utilizador Normal e o Administrador. Permite a um utilizador previamente registado autenticar-se no sistema para aceder à sua área reservada. Como pré-condição, o utilizador deve possuir uma conta previamente criada no sistema. Após a execução, a sessão do utilizador é iniciada com as permissões associadas ao seu respetivo perfil. No fluxo principal, o utilizador acede à página de login, introduz o seu Email e Password e clica no botão para entrar. O sistema valida as credenciais introduzidas e, estando corretas, inicia a sessão e encaminha o utilizador para o painel principal correspondente ao seu perfil. No fluxo de exceção, se as credenciais forem incorretas, o sistema lança a exceção LoginInvalidoException e informa o utilizador de que o email ou a password introduzidos são inválidos.

UC03 - Consultar e Editar Perfil
Este caso de uso aplica-se ao Utilizador Normal e ao Administrador. Permite ao utilizador consultar as suas informações pessoais e atualizar dados como o nome ou a password. Como pré-condição, o utilizador tem obrigatoriamente de estar autenticado no sistema. Como pós-condição, os dados do perfil são atualizados na base de dados ou ficheiro de persistência. No fluxo principal, o utilizador acede à secção dedicada ao seu perfil, onde o sistema apresenta os dados atuais registados. O utilizador altera os campos pretendidos e clica na opção de guardar. O sistema valida os novos dados, aplica as alterações e exibe uma mensagem de confirmação ao utilizador.

Módulo 2: Gestão de Espaços e Equipamentos
UC04 - Consultar Espaços Desportivos
Este caso de uso tem como atores o Utilizador Normal e o Administrador e não exige qualquer pré-condição ou pós-condição de alteração de estado. Permite visualizar a lista de espaços desportivos disponíveis, bem como as suas características detalhadas. No fluxo principal, o utilizador acede à página de espaços desportivos, onde o sistema apresenta a lista completa de recintos existentes, tais como campos de futebol, courts de ténis, pavilhões ou salas de fitness. O utilizador pode aplicar filtros por tipo de espaço ou estado de disponibilidade. Ao selecionar um espaço específico, o sistema exibe os detalhes completos, a capacidade máxima e os equipamentos associados.

UC05 - Gerir Espaços Desportivos (CRUD)
Este caso de uso é exclusivo do ator Administrador. Permite adicionar novos espaços desportivos, editar informações de espaços existentes, alterar o seu estado de disponibilidade ou removê-los do sistema. Como pré-condição, o utilizador tem de estar autenticado com o perfil de Administrador. A pós-condição garante que o catálogo de espaços desportivos é devidamente atualizado. No fluxo principal, o administrador acede à área de gestão de espaços e escolhe a operação pretendida entre criar, editar, alterar estado ou remover. Caso esteja a criar ou editar, preenche os campos do Nome, Tipo de Espaço, Localização e Capacidade Máxima. Após a confirmação, o sistema valida e guarda as alterações na lista de espaços. No fluxo de exceção, caso se tente remover um espaço que possui reservas ativas, o sistema lança a exceção EspacoComReservasException e impede a eliminação do recinto.

UC06 - Gerir Equipamentos
Este caso de uso é realizado pelo Administrador. Permite gerir o inventário de equipamentos desportivos associados aos diferentes espaços, definindo as quantidades disponíveis e o seu estado de conservação. Exige como pré-condição que o utilizador seja um Administrador autenticado. Como pós-condição, o inventário de equipamentos fica atualizado e associado ao respetivo recinto. No fluxo principal, o administrador seleciona o espaço desportivo pretendido e opta por adicionar um novo equipamento ou editar a quantidade e o estado de um equipamento existente. O sistema valida os dados introduzidos e atualiza o registo no sistema.

Módulo 3: Gestão de Reservas
UC07 - Criar Reserva
Este caso de uso tem como ator principal o Utilizador Normal. Permite a um utilizador efetuar o pedido de reserva de um espaço desportivo para um determinado dia e intervalo de horas. Como pré-condição, o utilizador deve estar autenticado e o espaço desportivo deve estar no estado Disponível. Como pós-condição, a reserva é registada com o estado Pendente. No fluxo principal, o utilizador escolhe o espaço desportivo desejado, seleciona a data, a hora de início e a hora de fim, e submete o formulário de reserva. O sistema verifica se não existem sobreposições de horário no mesmo espaço e se as datas são válidas. Não havendo conflitos, o sistema regista a reserva no estado Pendente e apresenta uma mensagem de confirmação do pedido. Nos fluxos de exceção, caso o horário já esteja ocupado por outra reserva, o sistema lança a exceção ConflitoHorarioException, recusa o pedido e solicita a escolha de um novo horário. Caso o utilizador tente reservar sem estar autenticado, o sistema lança NaoAutenticadoException e redireciona para a página de login.

UC08 - Consultar Minhas Reservas
Este caso de uso tem como ator o Utilizador Normal. Permite ao utilizador consultar o histórico de todas as reservas efetuadas por si e verificar o estado em que cada uma se encontra. Requer como pré-condição que o utilizador esteja autenticado. Não altera o estado do sistema. No fluxo principal, o utilizador acede ao menu das suas reservas e o sistema devolve uma lista com o histórico completo, apresentando para cada item a data, o horário, o espaço reservado e o estado atual da reserva, designadamente Pendente, Confirmada, Cancelada, Concluída ou Expirada.

UC09 - Cancelar Reserva
Este caso de uso pode ser executado pelo Utilizador Normal ou pelo Administrador. Permite anular uma reserva previamente efetuada. Como pré-condição, a reserva a cancelar deve encontrar-se no estado Pendente ou Confirmada. Como pós-condição, a reserva passa para o estado Cancelada e o espaço fica livre para esse intervalo horário. No fluxo principal, o utilizador ou administrador seleciona a reserva pretendida na lista, clica na opção de cancelar e confirma a ação na janela de validação. O sistema altera de imediato o estado da reserva para Cancelada e liberta a agenda do espaço.

UC10 - Aprovar ou Recusar Reserva
Este caso de uso é desempenhado exclusivamente pelo Administrador. Permite analisar os pedidos de reserva pendentes e decidir pela sua aprovação ou rejeição. Como pré-condição, a reserva selecionada deve estar obrigatoriamente no estado Pendente. Como pós-condição, o estado da reserva muda para Confirmada ou Cancelada. No fluxo principal, o administrador acede à lista global de reservas pendentes, seleciona a reserva que deseja analisar e escolhe a opção de aprovar ou recusar. Se aprovar, o sistema altera o estado da reserva para Confirmada, bloqueando o recinto para esse horário; se recusar, altera o estado para Cancelada.

Módulo 4: Administração, Relatórios e Processos do Sistema
UC11 - Gerir Utilizadores
Este caso de uso tem como ator o Administrador. Permite visualizar a listagem completa dos utilizadores registados na plataforma e efetuar a gestão dos seus perfis e permissões. Exige como pré-condição que o administrador esteja devidamente autenticado. Como pós-condição, as permissões dos utilizadores ficam atualizadas. No fluxo principal, o administrador acede ao painel de gestão de utilizadores, onde o sistema lista todos os registos existentes. O administrador pode filtrar ou pesquisar utilizadores específicos e alterar a atribuição do seu perfil entre Utilizador Normal e Administrador.

UC12 - Visualizar Relatórios e Estatísticas
Este caso de uso é executado pelo Administrador. Permite analisar os indicadores de utilização das instalações desportivas através de dados consolidados. Requer como pré-condição a autenticação como Administrador. Não produz alterações de dados. No fluxo principal, o administrador acede ao menu de relatórios e o sistema gera e apresenta estatísticas sobre o número total de reservas, a distribuição de reservas por espaço e período temporal, os espaços com maior volume de utilização e a taxa global de ocupação das instalações.

UC13 - Expirar Reservas Automaticamente
Este caso de uso é executado automaticamente pelo ator secundário Sistema. Permite invalidar reservas que não foram confirmadas dentro do período de tempo estipulado. Como pré-condição, devem existir reservas no estado Pendente cujo prazo limite de confirmação foi ultrapassado. Como pós-condição, essas reservas assumem o estado Expirada. No fluxo principal, o sistema executa periodicamente uma tarefa em segundo plano que verifica as reservas pendentes, identifica aquelas que excederam o tempo limite sem validação do administrador e atualiza o seu estado para Expirada de forma automática.

UC14 - Concluir Reservas Finalizadas
Este caso de uso é executado automaticamente pelo ator secundário Sistema. Permite atualizar o estado de reservas já efetuadas após o término do período de utilização. Como pré-condição, devem existir reservas no estado Confirmada cuja data e hora de fim sejam inferiores à data e hora atual. Como pós-condição, o estado da reserva passa a Concluída. No fluxo principal, o sistema monitoriza continuamente as reservas confirmadas, compara a hora de fim da reserva com o horário atual do servidor e altera o estado da reserva para Concluída assim que o horário de utilização tiver terminado.
